# Browser to record

This guide covers Ubuntu 26.04 prerequisites, running the automated release
verifier, building and running the compiled `mf_exam` Mix release directly, the
manual listening check, and optional local workspace SDK testing.

## Prerequisites (Ubuntu 26.04)

1. **System packages:**

   ```bash
   sudo apt-get install -y git curl tar build-essential pkg-config libssl-dev jq openssl
   ```

   *(Install `libopus-dev` as well if compiling `membrane_opus_plugin` from
   source instead of using precompiled binaries.)*

2. **Pinned runtimes (`.tool-versions` via `asdf` or `mise`):**
   - Erlang `29.1.2`
   - Elixir `1.20.5-otp-29`
   - Node.js `24.19.0` (required for `--integration` / Chromium verification)

3. **Native services (or external URLs):**
   - **PostgreSQL 18** server binaries (`initdb`, `pg_ctl`, `createdb`, `psql`),
     or an existing test database via `DATABASE_URL`.
   - **Temurin JDK `21.0.9+10`** (full JDK with `javac 21.0.9`) with `JAVA_HOME`
     set when using the built-in local HAPI FHIR 7.6.0 runner, or an existing R4
     FHIR server via `FHIR_BASE_URL`.

## 1. Automated release verification

```bash
./onboard.sh --integration
bash ops/verify_browser.sh --release
```

The verifier builds the `mf_exam` Mix release, opens separate patient and
clinician Chromium contexts, and exercises:
- Direct WebRTC conversation + patient reload rejoin,
- Live Chromium microphone capture through the `AudioWorklet`,
- Clinician diagnostic preview peer replacement mid-capture,
- Exam release restart recovery of the finalized WAV and manually entered pulse rate,
- Separate atomic acceptance and FHIR R4 read-back from HAPI (including HAPI
  restart when the runner owns HAPI).

Set `DATABASE_URL` and `FHIR_BASE_URL` to target dedicated external test
services, or leave both unset to let `ops/local_services.sh` start isolated
native PostgreSQL 18 and HAPI 7.6.0 instances in the run directory. Never point
verification at a production database or FHIR server—it inserts synthetic
clinical records.

## 2. Build and run the compiled Mix release (`mf_exam`)

Use these steps to build and start the compiled OTP Mix release directly (for
example for local operation or the manual headphone listening check).

### Step A — Install dependencies, start services, and seed FHIR references

From the repository root, install Mix dependencies on a fresh checkout:

```bash
./onboard.sh
```

Start local native PostgreSQL 18 and HAPI FHIR 7.6.0 (or export your own
`DATABASE_URL` and `FHIR_BASE_URL`):

```bash
eval "$(bash ops/local_services.sh start)"
```

Seed the synthetic FHIR `Patient` and `Encounter` references before enabling
`MF_LAB`:

```bash
export MF_EXAM_ID="exam-local-1"
export MF_REFS_FILE="$PWD/_build/local-refs.json"
mkdir -p "$(dirname "$MF_REFS_FILE")"
(cd apps/exam && env -u MF_LAB mix run --no-start ../../ops/seed_exam.exs)
```

### Step B — Build the Mix release

```bash
(cd apps/exam && env -u MF_LAB MIX_ENV=prod mix release --overwrite)
```

### Step C — Configure runtime variables and start

| Variable | Requirement |
| --- | --- |
| `MF_LAB` | Set to `1` to enable the single-encounter exam configuration. |
| `MF_EXAM_ID` | `1–48` ASCII letters, digits, or dashes (`[a-zA-Z0-9-]+`); must match `MF_REFS_FILE`. |
| `MF_REFS_FILE` | Path to the JSON file generated by `ops/seed_exam.exs` for this `MF_EXAM_ID` and `FHIR_BASE_URL`. |
| `DATABASE_URL` | PostgreSQL connection URL (`postgres://...` or `postgresql://...`; supports `sslmode=disable` or `sslmode=verify-full`). |
| `FHIR_BASE_URL` | Base URL of the HL7 FHIR R4 endpoint (must match `MF_REFS_FILE`). |
| `MF_ARTIFACT_DIR` | Writable directory for immutable `<file_sha256>.wav` artifacts. |
| `MF_SECRET_KEY_BASE` | Phoenix signing secret of at least 64 bytes (e.g. `openssl rand -hex 48`). |
| `MF_PATIENT_ACTOR` / `MF_CLINICIAN_ACTOR` | Non-empty, distinct actor identifiers. |
| `MF_PATIENT_ACCESS_KEY` / `MF_CLINICIAN_ACCESS_KEY` | Distinct access keys of at least 32 bytes each (e.g. `openssl rand -hex 24`). |
| `MF_HTTP_PORT` | Optional HTTP bind port on `127.0.0.1` (defaults to `4000`). |

> **Schema initialization:** When `MF_LAB=1` is set, `MedFabric.Exam.Application`
> automatically runs `MedFabric.Store.Postgres.migrate/0` (applying
> `core/store/priv/sql/002_evidence.sql` idempotently under an advisory lock)
> and opens the encounter row in PostgreSQL on startup.

```bash
export MF_LAB=1
export MF_ARTIFACT_DIR="$PWD/_build/local-recordings"
export MF_SECRET_KEY_BASE="$(openssl rand -hex 48)"
export MF_PATIENT_ACTOR="patient-1"
export MF_CLINICIAN_ACTOR="clinician-1"
export MF_PATIENT_ACCESS_KEY="$(openssl rand -hex 24)"
export MF_CLINICIAN_ACCESS_KEY="$(openssl rand -hex 24)"
export MF_HTTP_PORT=4000

apps/exam/_build/prod/rel/mf_exam/bin/mf_exam start
```

*(For development without building a release, run `cd apps/exam && mix run --no-halt`
with the same environment variables.)*

Stop the release with `Ctrl-C` (or `apps/exam/_build/prod/rel/mf_exam/bin/mf_exam stop`
when started with `daemon`), and stop local services afterward with:

```bash
bash ops/local_services.sh stop
```

> **HTTPS requirement for non-localhost browsers:** Browsers only expose
> `navigator.mediaDevices.getUserMedia` and `AudioWorklet` in a secure context
> (`https://`, or `http://localhost` / `http://127.0.0.1`). The lab runtime
> config binds `127.0.0.1` and restricts `check_origin` to `localhost` and
> `127.0.0.1`; terminate TLS and update `url`/`check_origin` (and replace the
> lab key gate with real authentication) before serving across a network.

## 3. Manual headphone listening check

With the compiled release (or `mix run --no-halt`) running from Section 2:

1. Open `http://127.0.0.1:4000/encounters/$MF_EXAM_ID?key=$MF_PATIENT_ACCESS_KEY`
   in one browser profile and `?key=$MF_CLINICIAN_ACCESS_KEY` in a separate
   browser profile. Use headphones.
2. Join the WebRTC conversation from both profiles and confirm two-way audio is
   clean in both directions.
3. Open the diagnostic preview as clinician, then start live capture as patient
   using a real microphone. Listen, disconnect the clinician preview, reconnect
   it, and listen again before the patient finishes capture. Confirm preview
   disconnect leaves capture running.
4. Play back the finalized WAV recording as clinician. Enter a measured pulse
   rate, explicitly accept both items, and deliver each to the test FHIR
   service.
5. Record the browser version, microphone model, observed audio quality before
   and after reconnect, and any issues.

## 4. Verify a local `med_ex` workspace checkout (MWO)

Until `:med_ex` `0.1.0` is published on Hex.pm, `apps/exam/mix.exs` pins a
committed `med_ex` projection ref. To test against a local sibling `../med_ex`
checkout instead using `mix_workspace_ops` (optional developer-workspace flow):

1. Run `mix weld.project` in `../med_ex`.
2. Run the release verifier with the private medical workspace registry:

```bash
mix_workspace_ops run --project med_fabric.mf_exam --mode local \
  --registry "$HOME/.config/mix_workspace_ops/medical/registry.json" \
  --checkout-root .. --timeout 12m -- \
  bash -c 'set -e; mix deps.get; exec bash ../../ops/verify_browser.sh --release'
```

## 5. Focused test suites

- `mix test` from the repo root runs all child unit suites.
- `cd core/store && mix test integration` verifies SQL rollback and competing
  acceptance against PostgreSQL (`DATABASE_URL` required).
- `cd core/interop && mix test integration` verifies HAPI FHIR R4 read-back and
  retry after a lost response (`FHIR_BASE_URL` required).

See [Architecture and roadmap](architecture_and_roadmap.md) for ownership,
database/FHIR contracts, and the planned capability families.
